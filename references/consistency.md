# 编号与提交一致性核查

论文插进一张新表或一条新公式后，后面所有编号都会平移。这类漂移 LaTeX 不报错，`check_submission.py` 也不报错，因为引用本身仍然有效，只有逐条核对才看得出来。本节把这类问题变成可机验的退出码，对应 [review.md](review.md) 第 2 类审查。

脚本：[scripts/check_consistency.py](../scripts/check_consistency.py)。

## 一、编号一致性的三层核查

三层都要查，漏一层就留错。

第一层，源码引用层。每个 `\label` 至少被一个 `\ref` 引用，每个 `\ref` 都指向存在的 `\label`。未被引用的 label 说明某个图表写了却没在正文里指认，读者不知道该看哪一处。

第二层，正文写死层。正文里写死的 `表 3`、`图 2`、`第 6.2 节`、`§6.1`、`式 (9)` 不随浮动体移动，一旦在前面插表就会整体指错。真实案例：正文前面插入两张表后，9 处写死的公式号与 2 处写死的章节号全部平移，而编译日志与引用检查都是绿的。改法是全部换成 `\ref` 或 `\eqref`。

第三层，代码注释层。附录代码的注释与 print 标签常写着 `论文表 3`、`表 2 温度`。真实案例：四个求解脚本里 13 处注释与 6 处 print 标签是旧编号，正文插入两张表后整体偏移 2。改法是把编号换成稳定的文件名，例如 `对应 tables/tab3.tex`，这样正文增删浮动体都不会再漂移。

判定：`\ref` 指向不存在的 label 属阻断项；写死的编号与未被引用的 label 属警告项，逐条判断是改成 `\ref` 还是保留（例如题面本身的编号、代码里的数组下标不需要改）。

## 二、附录代码完整性

竞赛与多数报告类提交都要求附录包含全部可运行源程序，这是硬条款：缺程序、程序跑不通、结果对不上都可能取消评奖资格。而清单里逐个人工比对最容易漏。

做法是数两个集合。一是代码目录下的源文件（`.py`、`.m`、`.jl`、`.r`、`.c/.cpp`、`.sh`、`.js`、`.sql`、`.ipynb` 等），二是正文里全部 `\lstinputlisting` 的目标文件名。两个集合必须对齐。

真实案例：支撑材料 `codes/` 有 21 个脚本，附录只挂了 18 个，漏掉的两个恰好都是有结果进正文的脚本（参数不确定度传播、二维网格加密稳定性）。这类缺口看表格列不出来。

例外要写清。跨题协作脚本、一次性探索脚本、扫描器这类不进入本题支撑材料的文件，应在 README 的文件清单里点名说明为什么不在附录，而不是让检查静默放过。

## 三、页数配平

页数上限是硬约束，但常见做法是先写完再压缩，顺序错了会白删内容。目标区间按投稿要求设，数学建模竞赛常用的口径是正文 22 至 25 页、附录 20 至 30 页，官方上限更宽，但超区间会被判为行文啰嗦。

压缩优先动版式，最后才动内容。按下面的顺序做，一份正文 28 页、附录 31 页的稿子可以压到 24 与 30 页且不删任何结论。

- 正文表格统一到 `\footnotesize`，数据表不需要 `\small` 的字号。
- 整幅插图宽度从 `0.92\textwidth` 收到 `0.76\textwidth`，双图并排的保持 `0.48\textwidth`。
- 只被引用一次的公式改成行内写法，正文不再为它单独占一行。
- 段间重复合并，同一结论的不同角度明确分工。
- 附录里每一段代码的标题用 `\paragraph` 而不用 `\subsection`，二十来段就能省掉二十处小节竖向空白。
- 摘要是单独一页的硬指标，要卡满一页且不溢出，关键词必须落在同一页。

附录定位靠标题行。脚本默认取第一个以“附录”开头的标题行所在页，允许前置 `A.` 或 `1` 这类小节标号，因此正文里的 `见附录 3` 不会误判。标题行格式特殊（例如只有 `A 操作规范`、没有“附录”二字）时，用 `--appendix-marker` 换标记词，或直接 `--appendix-page 25` 指定起始页。

## 四、字体缺字

附录代码里的 `①`、`②`、`∝`、`≥` 这类字符可能落在等宽字体之外，编译日志会给出

```
Missing character: There is no ① (U+2460) in font [lmmono8-regular]
```

PDF 里对应位置是空白框，正文与附录都看不出来。真实案例：新加的两段分析脚本注释里用了 `①②∝`，编译日志报了 4 处缺字。改法是把这些字符换成中文词或 ASCII，再重编译。

所以每次改完附录代码，编译日志要扫一遍缺字，不能只看有没有 `!` 错误。

## 五、跑法

```bash
# 论文目录 + 代码目录；自动找目录内最新的 .log 与 .pdf
python scripts/check_consistency.py paper/ --codes codes/

# 完整指定，并收紧页数目标
python scripts/check_consistency.py paper/ --codes codes/ \
    --pdf paper/main.pdf --log paper/main.log \
    --body-range 22-25 --appendix-range 20-30

# CI：警告也算失败
python scripts/check_consistency.py paper/ --codes codes/ --strict
```

常用选项

- `--codes`：附录代码目录，可重复；缺省取论文目录同级的 `codes/`。
- `--log` / `--pdf`：编译日志与产物；缺省取论文目录内最新的同名文件。
- `--appendix-marker` / `--appendix-page`：附录定位方式，后者直接给页码。
- `--body-range` / `--appendix-range`：页数目标区间，格式 `A-B` 或 `N`。
- `--max-per-kind`：每类警告最多列几条，默认 5，看全量给 999。
- `--exclude`：路径含该子串时跳过，可重复。

退出码 0 表示没有阻断项，1 表示有阻断项；加 `--strict` 时警告也算阻断，便于接进提交流水线。
