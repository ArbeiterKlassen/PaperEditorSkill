# 七类审查

审查给出 PASS 或 FAIL，每类附证据清单。出现 FAIL 就修复，修复后全量重跑，不只查改动处。

## 1. 数值一致性

检查范围：正文、摘要、表格、图注中的每个数字。

方法：把正文数字与数据源逐一比对。数据源可以是 CSV、复算脚本或文献。正文数字必须与冻结口径一致，不能估计来源。

同一事实出现在多处时，所有位置必须用同一个值。摘要、图注、正文、表格、图里的同一数量要逐一核对。真实案例：外推误差在摘要与 teaser 图注里写 2%，正文与表格里写 1.3%，两处都是指同一个量，提交前必须统一。

记录每个数字出现的文件与行号，按数量逐个核对。

判定：全部一致为 PASS。发现一个不一致即为 FAIL，记录不一致的位置与正确值。

## 2. 交叉引用与编译

检查范围：图表编号、公式编号、引用键、主文与附录的互引、import 与代码路径。

方法：编译项目，检查日志中的 undefined reference 与 undefined citation；核对图与表编号和正文引用一致；代码部分做语法审计。

用 [scripts/check_consistency.py](../scripts/check_consistency.py) 把这一层变成可机验的退出码：三层编号（源码 label 与 \ref、正文写死的表号图号公式号章节号、代码注释里写死的编号）、附录代码完整性、正文与附录页数、编译日志字体缺字。做法与真实案例见 [consistency.md](consistency.md)。

主文里写到的每个附录（如 Appendix~J）必须在补充材料中存在，正文每个 \cite 都要有对应条目。参考文献的 key 年份与条目年份要一致，真实案例：key 为 liao2022kitti360 的条目年份是 2023，key 为 he2026linext 的条目年份是 2025，这类不一致要修正。

判定：编译通过且无未定义引用为 PASS。任何未定义引用、断链或语法错误为 FAIL。

## 3. 匿名合规

仅匿名投稿或匿名评审版本需要执行。

检查范围：
- 文本层：作者中英文名、机构、绝对路径，如 /home/xxx、/data1/xxx。
- 二进制层：ckpt 等文件中内嵌的路径字符串。
- 元数据层：MANIFEST、训练日志、压缩包内文件清单。
- 源文件层：tex 里的注释与被注释掉的作者块。真实案例：投稿版 tex 里保留着被注释的相机就绪作者块，中文注释里写了真实姓名与机构，匿名评审拿到的源文件会泄漏身份。
- 打包层：备份文件、旧版本文件不得进提交包，如 figures 目录里的 *_backup.pdf。

判定：作者身份信息全部删除为 PASS。第三方署名属于正当 credit，必须保留。

## 4. 表述清理

检查范围：AI 痕迹与语言规范。

方法：按 [writing.md](writing.md) 检查。删除 FIX、TODO、版本考据、调参轶事；中文注释改简洁英文；符号 ASCII 化；检查排比堆砌、长难句、空泛大词。

版本考据还包括旧版本号残留，真实案例：references.bib 头注释写着 v11 且声称 key 匹配 paper_full_v11.tex，实际是 v21 的包。这类注释在提交前删掉。

标题、摘要与引言的内容对照按 [writing.md](writing.md) 的"标题、摘要与引言的对照核查"执行，三处 claim 必须一致。

段间重复。相邻段落说同一件事时，精简后段只保留最相关的一处；不同段落讲同一结论的不同角度时，明确分工，避免冗余。真实案例：几何下界作用段与诊断指向干预段都讲下界引出惩罚，合并后各自定位清晰。

术语统一。同一对象不能用多种称呼，同一术语不能用两种叙述。同一对象的多种称呼（如预测点云、输出点云、补全点云）需在术语定义里明确对应；同一操作的不同表述（如加权求和、之和、相加）需统一。详细规范见 [patent.md](patent.md) 第三节。

易混词区分。两个明确有区别但名词相近的概念不能混为一谈（如覆盖度几何下界与精度下界、放置质量与覆盖度间隙因子），需明确基准差异并统一命名，在定义处写清区别。详细规范见 [patent.md](patent.md) 第三节。

判定：无内部痕迹且语言达标为 PASS。

## 5. 可复现性

检查范围：依赖清单、路径、claim 与证据的可验证性。

方法：requirements 完整；路径全部相对化；README 或附录给出 claim 到证据的对照，让读者能复算。

会议要求提交可复现性 checklist 时，逐题核对答案与论文内容一致，并把 checklist 编译进提交包。图与表里的数字能追溯到数据文件，绘图脚本指向数据源而不是备份文件。

判定：按文档能复现为 PASS。

## 6. 参考文献核查

检查范围：每条文献的真实性、数量与格式。

方法：用 [scripts/check_references.py](../scripts/check_references.py) 检查 .bib 的结构，加 --tex 时核对 thebibliography 与 bib 的年份一致性，加 --online 时对 arXiv ID 与 DOI 联网核验。没有 arXiv 或 DOI 的条目，用标题加作者人工检索。AI 生成的内容经常编造来源，作者、标题、年份组合搜不到结果的条目一律视为可疑。

数量：会议、期刊、报告对参考文献数量的要求不同，写作前与用户核实，不按默认值。AAAI 这类会议对参考文献页数有要求，正文页数与文献页数分开核对。

判定：全部文献真实存在且数量符合要求为 PASS。任何一条无法核实的文献为 FAIL。

## 7. 创新与对比核查

检查范围：通用框架提炼、常规算法对比、SOTA 点数据支撑、不确定度报告。

方法：
- 多个小问是否提炼为针对该类问题的通用模型，正演、逆问题、估计器是否完整。
- 是否复现领域常规算法，并在同一数据上对比，对比表是否给数值。
- SOTA 点是否具体，是否有数据支撑，不写空泛表述。
- 统计不确定度与系统不确定度是否分开报告。

判定：通用框架完整且有数据对比为 PASS。只有解题没有对比或 SOTA 点无数据支撑为 FAIL。
